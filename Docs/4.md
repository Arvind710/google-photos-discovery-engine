## 4. Phase 3 design (D-9, commit `422de42`)

### 4.1 The two open decisions — settled by the PM ("go with your recommendations")

- **2.2 (cue accuracy):** one `story_codes` row per remembered cue. The cue, a 2.1 value, goes in `value`; the judgement goes in `accuracy`.
  - A story with no revealed accuracy gets one row, `2.2 = not_stated`, with `accuracy` NULL.
  - The fixtures' `2.2: [certain_wrong]` expectations are scored against `accuracy`.
- **`metric_node`:** a fixed rule in code, `classify.blocks.metric_node(stage, codes, outcome)`:
  - 0 → `target_retrievable`;
  - 2, 4 → `query_captures_usable_cue`;
  - 3 → `enters_gp_retrieval_path`;
  - 5 → `target_ranked_visible` if 5.4 has a substantive value, else `query_captures_usable_cue`;
  - 6 → `user_recognises_target`;
  - 7, 8 → `found_after_refinement` if 7.2 has a tactic other than `quit` and the outcome is `found` or `found_after_struggle`, else `refines_instead_of_quitting`;
  - 1 → `context`;
  - 9, 10 → `outcome_measure`.

### 4.2 Also decided in code

- `failure_owner` comes from the spine map (`codebook.failure_owner`).
- `severity`:
  - the model scores `stakes`, `effort` and `emotional_intensity` 0–2;
  - the outcome part comes from `outcome` (`OUTCOME_SEVERITY`);
  - the total maps to 1–5 by `severity_v1.yaml`.
- **10.3** is structural. Its value comes from the source:
  - play/appstore → `reviews`;
  - reddit → `reddit`;
  - gp_help/stackexchange/quora/hackernews → `community_forums`;
  - youtube → `other:youtube_comments`;
  - x → `other:x_posts`.
  - (The codebook has no YouTube or X value; this is why T-12 excludes 10.3.)
- `mode_used` is the first 3.2 value. `urgency` is the `urgency:*` value of 1.4.
- **Video → adjacent:** if `media_type = video`, the story's bucket is set to `adjacent` with reason `video_out_of_scope: media_type coded video` (P3-INV-9).
- **Evidence:**
  - every quote is located in `text_clean` by `validate/spans.py`;
  - the search covers the story's own span and the same author's later posts only;
  - whitespace and quote-style tolerance is the same as Pass 1;
  - the match must be ≥ 15 characters;
  - the stored span is the matched slice;
  - `primary_stage` and `failure_owner` share the primary-stage quote.
  - **A story whose primary_stage quote is not found is re-coded once, synchronously, then marked `span_unverified` at stage `code` with its story_id** and not written.
  - Secondary quotes that are not found are dropped and counted (`quote_unverified`); the code itself stays.
- **Queries:** the literal queries a story reports go to the `queries` table only if the text appears (case-insensitive) in `text_clean`.
- **`other`:**
  - `other` plus `o` (text) becomes `other:<slug>`;
  - text that spells a listed value becomes that value (added in D-10);
  - `other` with no text becomes `other:unspecified`.

### 4.3 One request per story (the plan wrote four block prompts)

- **Prompt** = `prompts/code_v1.md` (header: rules, spine, severity rubric, "calls that are easy to get wrong") + `render_codebook(cb)`.
  - `render_codebook(cb)` is generated from `journey_v1.yaml`: spine boundary notes, every stage, every question with values, value_notes, boundary notes and value_boundary.
  - About 6.3k tokens, identical for every request, so the Batch API caches it: **86% of input tokens were cache hits.**
- **Schema:** built per story from its question set (`schema(cb, qids)`).
  - Keys are short to save output tokens: each question is `q5_3: {v, o, q}` (value(s), other text, quote); 2.2 is `{cues: [{cue, accuracy}], q}`.
  - Plus `spine` and `queries`.
  - The full core schema has 594 enum values (under the 1,000 strict-mode limit) and 59 questions.
- **Which questions:**
  - **core: A+B+C+D+R**, all 59 bank questions. S (10.3) is set in code.
  - **adjacent: A, +C if `reaches_stage` ≥ 5, +D if ≥ 7.**
- **Why:**
  - Stories are 200–400 characters, so the codebook is the input, and one call shares the reasoning across blocks.
  - With 115 core stories, the plan's "~70-story pilot on all 60 questions" would have been most of the core. So the pilot and the coverage register are the same run.
  - It also measures block yield BELOW the reach gate, the EC-SEG-5 check (§10).
- **Reasoning effort by bucket:** core `low`, adjacent `minimal` (`EFFORT_BY_BUCKET`).
  - Measured on one story: `low` = 3,631 output tokens, 2,240 of them reasoning; `minimal` = 1,461.
  - Everything at `low` would have left too little for P4 and P5.
  - The token probe is run `code-probe-20260926-114856-2ad6e6`, $0.067.

### 4.4 Commands (`python -m pipeline.classify.blocks …`)

| Command | What it does |
|---|---|
| `prompt` | Prints the full system prompt |
| `fixtures [--batch]` | Codes the 40 authored stories (all blocks; effort by expected bucket) and scores them. Writes `data/artifacts/code_fixtures_<run>.json` with per-row usage. `--batch` goes through the Batch API at half price (`batch_and_wait` polls every 30 s) |
| `estimate` | Projects the corpus cost from the latest fixture artifact: per-bucket output tokens × question fraction; input per request; the cached share as measured |
| `submit --yes` | Every live story not yet in `story_spine` and not marked at stage `code` (resume by diff, X-6). Refuses without `--yes` or if the projection would cross 1.5 × `ESTIMATE_USD` ($6.15) |
| `collect [--accept-overrun]` | Exits 3 until the batch finishes. Writes every cleanly coded story (clearing its old rows first), re-codes fatal ones ONCE synchronously (run `code-retry`), and marks what still fails. A request missing from the output stays un-coded for a later submit |
| `recode --yes` | Re-codes `stage0_suspects(con)` through Batch (run stage `code-recode`); `collect` replaces their rows |

Fatal results:
- `span_unverified`: the primary quote was not found;
- `coding_failed`: unparseable output;
- `model_refusal`: a refusal content item.

Each fatal response is saved to `data/quarantine/code_<story>.json` (gitignored).

## 7. The Stage 0 defect (found in the corpus, not the fixtures) — EC-CODE-18

- **What:**
  - After the corpus run, **52 of 115 core stories (45%) were coded primary_stage 0.**
  - That trips P3-MET-6's > 45% flag and would have inflated the headline "much can't-find is was-never-there" finding.
  - Of those 52: 17 had `0.1 = yes_backed_up`, 21 had `0.1 = not_stated`, 11 `deleted`.
  - Read one by one, many were **quiet successes**: "I just search for 'passport' and I can find it", "found my old baby photos", "they pop right up".
  - The codebook has no "nothing went wrong" stage, and the coder fell back to 0, whose failure owner is `library_data`.
- **Fix, part 1 (the prompt, v1.2):** "Stage 0 needs evidence; no failure is Stage 9." Stage 0 means the story SAYS the photo was unreachable. If nothing went wrong, the primary stage is 9 (owner `none`). A photo that "just won't show up", with nothing said about why, is not Stage 0.
- **Fix, part 2 (a check):** `blocks.stage0_without_evidence(stage, codes, outcome)` + `stage0_suspects(con)` + `recode`.
  - The first version flagged Stage 0 whenever 0.1 was `yes_backed_up`/`not_stated` and 0.2 had no wrong-data value.
  - **84 stories** (37 core, 47 adjacent) were re-coded: run `code-recode-20260926-122023-22367b`, $0.734; batch `batch_6ab7b88bb3a08190943d83a8f0a0e2b6`.
  - **One request stalled** at 83/84 for 20+ minutes. The batch was cancelled with `client.batches.cancel`; "cancelling" took ~25 minutes before the output file appeared.
  - `collect` wrote 79, re-coded 4 synchronously (`code-retry-20260926-130632-cc4b9e`, $0.083): 3 recovered, 1 `span_unverified`.
  - **The stalled story (1) keeps its v1.1 coding**; it is not a suspect under the final check.
- **After the re-code, 25 stories were still flagged, and reading them showed the CHECK was wrong.**
  - Nearly all SAY the photo vanished from the library: "it's vanished", "missing from May 2015, backup always on", "went missing after an update", "uploaded to the cloud and now can't find it in Archive".
  - That is a correct Stage 0, and the 0.1 note forbids naming a place the story does not state.
  - **The check was narrowed to the defect actually found:** Stage 0, the story ends with the photo `found`/`found_after_struggle`, and nothing in 0.1/0.2 says it was unreachable.
  - Under the final check, **0 remain** (test `test_no_stage0_story_without_library_evidence`).

  - 0 → 20;
  - 2 → 9, 3 → 9, 6 → 9;

## 18. Gotchas learned this session

1. **Only one Chrome profile is connected.** `switch_browser` reaches only Chromes whose extension is signed in and running.
2. **gpt-5 at `low` spends ~60% of its output on reasoning** (2,240 of 3,631 tokens for one story). `minimal` is ~2.5× cheaper, but it over-inferred outcomes on the probe.
3. **The Batch API caches the prefix:** 86–95% cache hits when the instructions are identical. Put the long, stable part in `instructions`.
4. **A single stalled request holds a whole batch**, and cancelling takes ~25 minutes before the partial output appears. Design `collect` to write what finished and resume by diff.
5. **OpenAI's billing hard limit can trip below the recorded spend.** Stop; don't retry.
6. **The authored fixtures had no quiet successes**, so a whole class of mis-coding (EC-CODE-18) surfaced only in the corpus. **Read a sample of the corpus coding by stage after every run**; don't rely on the fixtures alone.
7. **A consistency check needs reading too:** the first Stage 0 check flagged correct "photo vanished" stories. Narrow a check to the defect you saw.
8. **gpt-5-mini over-finds** (EC-VAL-8): stories (D-8), then themes (D-10). A gpt-5 confirm step fixes it cheaply.
9. **One `Run` per model.** `runs.Run` prices every token at its single model's rate.
10. **`met_or_limitation` stops at the first failing block in a loop**, and that hid C and D behind B. Look at every value.
11. **The P3 test reads the fixture artifact matching `PROMPT_VERSION`.** Bumping the prompt without re-running fixtures fails the gate, by design.
12. **Coverage and funnel must be rebuilt** after any re-code, or they go stale (`analyse.coverage`, `analyse.funnel`).
13. **`corpus.db` is 65 MB** (60.25 MB at the last push warning). GitHub warns above 50 MB and refuses 100 MB. The release-asset route (arch §9) will be needed if collection ever grows.
14. **Foreground `sleep N; cmd` is blocked.** Use `until …; do sleep …; done` or `run_in_background`; a tool call times out at 600 s.
