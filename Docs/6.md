## 2. Latency measurements that shaped the design

The latency probe is at `scratchpad/latency.py` in the old session's scratchpad. It is not in the repo.

**Before the change:**

| Component | Setting | Time |
|---|---|---|
| Planner (gpt-5-mini) | reasoning `low` | 5–9 s |
| Planner (gpt-5-mini) | reasoning `minimal` | 3.4–5.8 s |
| Writer (gpt-5, `minimal`) | first token | ≈0.9 s |
| Writer (gpt-5, `minimal`) | full draft | 1.7–5.2 s |
| Repair | a second writer call | doubles the writing time |
| One hung API call | old `TIMEOUT_S=120` | up to 120 s |

The 63-second answers came from three causes together: the repair, the planner at `low`, and the long timeout.

**Conclusion:** 10 s is only possible if all of the following hold:
- the planner runs at `minimal`, with a hard cap;
- there is **no repair**;
- the writer streams, against a hard deadline;
- a fallback that is correct by construction replaces any draft that fails the check or runs late.

## 3. What was built (all uncommitted)

### 3.1 `app/lib/plain.py` — NEW: the translation layer

This module is deterministic and makes no model call.

**Purpose:**
- Every retrieved row becomes one plain English sentence with a tag:
  - `[F#]` a fact (an analysis row);
  - `[S#]` a post (a story, fenced as untrusted);
  - `[N#]` a note on what the evidence cannot show (a method flag).
- The writer sees **only** these sentences. It never sees a table name, key, stage number, question id or code value.
- `Tags.expand()` maps tags back to internal `[[table|key]]` citations, so every existing check still runs unchanged.
- `[F1, S2]` and `[F1][S2]` are both handled. An unknown tag is left as written, and the jargon check then fails it.

**Vocabularies:**

| Name | What it covers |
|---|---|
| `STAGE` | Plain clause per journey stage 0–10. Stages 9 and 1 have special sentences, so the text never reads "the first thing that went wrong was that nothing went wrong". |
| `KIND` | Photo classes. Sentimental → "photos kept as memories (people, trips, events)"; utility → "photos kept for the information in them (receipts, documents, notes)"; unclear, both. |
| `OUTCOME` | Full clauses per outcome. |
| `MEDIA` | Media types. |
| `FAMILY` | Cue families (who/what/where/when…). |
| `POP` | core → "about a photo the person only vaguely remembered"; adjacent → "about a photo the person knew exactly, or one already gone". |
| `SOURCE` | Plain source names. |
| `THEME` | The 4 emerging themes. |
| `FIELD` | Reliability field names. |
| `FLAG` | Plain rewrites of the 10 method flags. Every number in them is also in the stored flag text, so the number check passes. The DB flag texts were NOT changed, so no re-publish was needed. |
| `VALUE` | Plain labels for code values that do not read as English (e.g. `hard_filter_single_cue` → "one wrong detail hid the photo"). |
| `PREFIX` | Plain labels for value prefixes: path:, decisive_cue:, why:, fallback:, urgency:, … |

**Functions:**
- `question(qid)` returns the codebook question's `plain` line, lower-cased.
- `words(slug)` turns a code value into words.
- `count(n, d)` formats a count:
  - below 30: "6 of 21 stories";
  - 30 and above: "13 of 48 stories (27%)";
  - this is the same percentage `share()` prints.
- `rough(d)`: for 30 ≤ d < 80 the sentence ends "— a small group, so only a rough guide". This is the plain form of "directional".
- `sentence(row)` covers every table:
  - crosstab, derived, funnel, sources, coverage, reliability, method flags, opportunity, weight sensitivity, synthesis, themes;
  - rows with no plain form return None (metric_node, js_divergence, derived rows with n = 0).
  - It **adds plain keys to the row** for any number it computes, so `check_numbers` supports them: `stories_asked`, `stories_agreed`, `times_first`, `percent`.
- **No quotation marks in fact sentences.** The quote checker would treat a copied phrase as a fabricated quote.
- `desnake()` cleans the model-written recommendation and hypothesis text (analysis_synthesis):
  - spells out code names;
  - drops "Metric node:" prefixes and brackets.
- `JARGON` regex and `check_jargon(text)` flag internal words:
  - stage N, core, adjacent, corpus, coded, codebook, coder(s), cohort, dataset, directional, kappa, metric node, proxy, gated, crosstab, retrieval story;
  - utility photos/stories, question N.N;
  - FULL, PARTIAL and NONE in capitals only;
  - κ;
  - unexpanded `[F9]` tags.
  - Quotes and citations are ignored.
- `scrub(text)` rewrites stored text and the planner's restatement: Stage N, core stories, corpus, coders, stage → step, retrieval → finding the photo, failure mode, utility → practical, directional.
- `visible(text)`: what the page shows while streaming. Tags and half-arrived tags are removed, and double spaces collapsed.
- `build(got)` returns `Tags`:
  - facts (the first 30 plus rivals, coverage, reliability and totals, deduplicated);
  - then notes (flags);
  - then posts (records, 600 characters each, fenced).

### 3.2 `app/lib/analyst.py` — rewritten loop (`PROMPT_VERSION = "ask_v2.0"`)

**Settings:**
- `PLANNER_EFFORT = "minimal"` (was `low`).
- `BUDGET_S = 10.0`
- `PLANNER_TIMEOUT_S = 4.5`
- `CHECK_S = 0.5`, held back from the writer's deadline.
- `TIMEOUT_S = 30` (was 120). This is only the client default; every call sets its own via `_within(client, seconds)`, which calls `client.with_options(timeout, max_retries=0)`.

**Planner:**
- The prompt now says `restated` must be plain everyday words.
- It asks for 1–2 `sub_questions`, not 2–4, to cut output tokens.
- `plan(client, q, history, timeout=)`.

**`rule_plan(question)`:** used when the planner times out.
- Builds a plan from the question's own words.
- Runs `R.normalise_plan`'s SUBJECT_RULES plus `_RULE_SUBJECTS` (opportunity, method, theme).
- Adds the default queries and evidence kinds.
- `Answer.planned_by = "rules"`.
- A planner error that is **not** a timeout (e.g. insufficient_quota) still returns `a.error`, so `caps.explain` can say "paused".

**`SYNTHESIS_SYSTEM`:** a new plain prompt.
- Written for a stranger; 40–90 words.
- Built on the 1–3 facts that answer the question most directly.
- A tag after every sentence.
- Numbers copied exactly; the "rough guide" words kept.
- The proxy rule, stated plainly.
- Quotation marks only around a post's own words.
- One note [N].
- A list of forbidden words.
- No label with a colon.
- An italic closing question.
- The FULL / PARTIAL / NONE rules.
- The injection rule.

**`brief(p, got, v, question, tags)`:** **the signature changed** (it now takes `tags`). It contains:
- QUESTION;
- ANSWER TYPE;
- WHAT THE STORIES CANNOT TELL;
- TOO FEW FOR A PERCENTAGE;
- KINDS OF PHOTO (the rule against comparing kinds when all groups are under 80);
- WRONG ASSUMPTION (scrubbed);
- FACTS / NOTES / POSTS.

`_row_line`, `_story_block`, `_plain`, `_label` and `REPAIR` were **removed**.

**`_stream(client, text, deadline, on_text)`:**
- `responses.create(..., stream=True)`.
- `response.output_text.delta` → `on_text(so_far)`.
- Usage is read from `response.completed`.
- Past the deadline it raises `Late`.

**`finish(raw, tags, got)`:** expand the tags, then italicise the closing question, then the story-citation and canonical-citation fixes.

**`ABSOLUTE`:** adds `"internal word"`. A jargon failure withholds the draft.

**`_REASON_FLAG`:** keywords updated to match the new plain gate reasons: "agreed too rarely", "age or gender", "where people live", "across time", "which phone".

**`fallback()`:** rewritten in plain words.
- NONE: "These are public posts about trying to find a photo, not data on how people use Google Photos. {Reason}. Answering it would need data these posts do not hold."
- Otherwise, in order:
  1. "The stories cannot tell you all of this: {reasons}" with flag citations;
  2. the premise line;
  3. bullets of `P.sentence(row)` with citations;
  4. "- One of the posts this rests on, to read in full [[story|…]]";
  5. `FLAG["proxy_not_success_rate"]` with its citation;
  6. "*Want to ask it more narrowly?*".
- The old "I could not write an answer…" first line is gone. The page now shows a note instead (§3.4).
- `_pick()`: when the subject is `corpus` it returns the funnel totals. This fix came from the sweep: N1's fallback had shown no numbers.

**`ask(client, con, q, *, history, inject_stories, progress, on_text, budget_s=BUDGET_S)`**, in order:
1. Plan, with timeout; on a timeout, `rule_plan`.
2. `normalise_plan`; restated = `P.scrub(...)`.
3. Retrieve and inject stories.
4. Gate.
5. `P.build`.
6. Brief.
7. Stream with deadline `t0 + budget - CHECK_S`.
8. Check.
9. If there is an ABSOLUTE problem, or the draft was late: `a.withheld` = the problems (or "the draft did not finish within N seconds"), `a.draft` = the draft, text = fallback, then re-check.

**No repair.** `a.repaired` is always False.

### 3.4 `app/lib/retrieval.py` — gate reasons in plain words

These strings are shown to the reader on PARTIAL answers and in the fallback. `from lib import plain` was added.

- KIND_PHRASE:
  - opportunity → "how this ranks among the problems worth fixing";
  - hypothesis → "ideas to test in interviews";
  - reliability → "how reliably the stories were read";
  - theme → "the patterns noticed after the study was designed".
- MISSING_CUTS:
  - "the posts say nothing reliable about people's age or gender…";
  - "…about where people live…";
  - "the stories were not compared across time, so there is no before-and-after";
  - "the posts do not reliably say which phone people use, so there is no Android vs iPhone split";
  - "the stories do not compare how well other photo apps search".
- Floor reasons:
  - "only N stories fit — too few (under 30) for a percentage…";
  - "none of the stories is about {plain kind}";
  - "only N stories are about {plain kind} — too few (under 30)…";
  - caveat "fewer than 30 stories are about …, so those get counts only".
- Register: "few public posts say anything about {plain question} — n of N stories do — so it is left for interviews with real users".
- Low reliability: "two AI readers went through the stories separately and agreed too rarely on {plain field} to rely on it".
- Verbatim: "no post matches it closely enough to quote" / "too few posts match it to quote from".
- NONE default: "nothing in the stories bears on this".

## 6. Decisions to record (not yet written into decisions.md)

**D-14 — Ask AI v2.0: the translation layer, streaming, a 10 s budget, no repair.** The PM gave this instruction on 2026-09-27.

1. **The writer sees only plain tagged sentences**, built by `plain.py`. Jargon in an answer is an **absolute** failure: the draft is replaced by the plain fallback. Words the asker typed are exempt.
2. **"Directional" said plainly.** A 30–79 share is written "n of N stories (x%) — a small group, so only a rough guide". The Wilson interval is **dropped from answers**; `share()` still prints it on the charts. The checker accepts "rough guide" as the label. This is a deliberate readability trade against [CTX] §15.5's "widened interval" — record it.
3. **10 s budget:**
   - planner at `minimal` with a 4.5 s cap, then `rule_plan`;
   - the writer streams with a deadline at 9.5 s;
   - **no repair** (EC-ASK-7's one repair is withdrawn);
   - a late draft is replaced by the fallback.
4. **Streaming shows the draft before the check.** A withheld draft is visible for about 1 s before the fallback replaces it, with a caption saying so. This reverses the "no streaming" decision in the old ask.py docstring (5.md §19). The PM asked for it. The risk to state: an injected instruction could be visible briefly.
5. **Page claim:** "about 15 seconds". Measured mean 7.2 s, maximum 9.1 s.
6. **Scroll:** the page holds at the start of the newest answer.
